  4. Gaps between existing endpoints and existing tests
                                                                                                                                        
  Completely untested endpoints
                                                                                                                                        
  Customer service — write side                                                                                                         
  - PATCH /customers/{id} — the general field-update endpoint has zero test coverage. No test sends a partial update.
  - PATCH /customers/{id}/flag — the manager-only priority flag endpoint is entirely untested. Neither the happy path nor the 403       
  (missing or non-manager X-User-Id) is exercised.                                                                               
  - PATCH /customers/{id}/assign — the rep-assignment endpoint is entirely untested.                                                    
  - PATCH /users/{id} — the user field-update endpoint has zero test coverage.      
  - DELETE /users/{id} — the administrator-only hard-delete endpoint is entirely untested.                                              
                                                                                                                                        
  Planning service — write side                                                                                                         
  - POST /plans/{plan_id}/calls — adding a call is never tested despite the endpoint existing and the confirm logic accepting calls as  
  an alternative to visits.                                                                                                             
  - PATCH /plans/{plan_id}/visits/{visit_id} — updating a visit's status or outcome_notes is never tested.
  - PATCH /plans/{plan_id}/calls/{call_id} — updating a call is never tested.                                                           
                                                                                                                                        
  Expense service — read side
  - GET /expenses/read/status/{status} — the path-param-based status filter read model endpoint has no test at all.                     
                                                                                                                                        
  Frontend service
  - All 8 HTML page routes are untested. No test file touches the frontend service.                                                     
                                                                                                                                        
  Health checks
  - No test verifies any of the four /health endpoints.                                                                                 
                                                                                                                                        
  Partially tested or missing scenarios
                                                                                                                                        
  CQRS read model — status transitions not fully covered                                                                                
  - GET /plans/read/history is tested for draft and confirmed states only. The activate and complete transitions are not verified in the
   history projection.                                                                                                                  
  - GET /expenses/read/history is tested for submitted and approved. Rejected and resubmitted status transitions are not verified in the
   read model.                                                                                                                          
  - GET /plans/read/history with the ?date filter is never tested.                                                                      
  - GET /expenses/read/history with the ?status filter is never tested.
                                                                                                                                        
  Expense service — state machine invalid transitions       
  - Approving a rejected or draft expense (not pending_approval) is not tested.                                                         
  - Rejecting a draft or already-rejected expense is not tested.                                                                        
  - Resubmitting an expense that was never rejected (i.e., still in submitted state) is not tested.                                     
                                                                                                                                        
  Role-based access control                                                                                                             
  - No test exercises the 403 response from PATCH /customers/{id}/flag when the X-User-Id header is absent or belongs to a non-manager. 
  - No test exercises the 400 response when X-User-Id is not a valid UUID.                                                              
                                                                          
  Plan state machine — invalid transitions not fully covered                                                                            
  - Activating a completed plan is not tested.                                                                                          
  - Completing a confirmed plan (skipping active) is not tested.                                                                        
  - Completing an already-completed plan is not tested.                                                                                 
                                                                                                                                        
  Visit added to non-draft plan
  - No test attempts to add a visit or call to a plan that is already confirmed, active, or completed. The service behaviour in these   
  cases is untested.                                                                                                                    
                                                                                                                                        
  GET /plans with ?rep_id filter returning actual results                                                                               
  - test_edge_cases.py tests the empty-list case for an unknown rep, but no test verifies that ?rep_id correctly returns only the target
   rep's plans when plans exist.                                                                                                        
                                
  GET /expenses with ?expense_status filter                                                                                             
  - The status query parameter on the write-side list endpoint is never tested.
